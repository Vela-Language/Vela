# Vela v0.5 计划：运行期函数对象与精确 GC

> 状态：进行中
> 基线：v0.4.0 稳定版（209 tests、差分 11/11、500 语料、boxed 全 strict）
> 目标版本：`0.5.0`

v0.5 把 v0.4 收口时留下的 3 个子项归并为两条主线：

1. **精确 GC**：live-OBJ 位图 + 循环终结器（对应 v0.4 例外 1、3）。
2. **运行期动态函数对象**：code 对象、跨函数传递/返回、动态调用（对应 v0.4 例外 2）。

同时补齐性能与 CPython 覆盖门槛，最终发布 `0.5.0` 稳定版。

## 1. 运行期动态函数对象

### 1.1 code 对象

- 新增 `code` 运行时类型：目标地址、arity、参数/返回布局标识。
- 模块容器中的函数值由占位 OBJ 替换为真实 code 对象。
- `sys.modules[名字].func` 取出的值可保存、传递、返回。

### 1.2 统一调用约定

- 为每个可动态调用的函数生成 boxed 参数 wrapper：数组入参、boxed 返回。
- `rt_function_call(code, args, argc)` 校验 arity 后间接调用 wrapper。
- 支持 0–4 个位置参数；超出范围显式报错。
- 返回类型未知时由 wrapper 返回 OBJ，调用点按静态类型拆箱。

### 1.3 动态调用落地

- 函数值作为参数传入、作为返回值传出后可继续调用。
- 模块函数值、局部函数值、`sys.modules` 路径共用同一 code 对象。
- 保留现有静态解析快路径；静态已知目标仍直接调用。

## 2. 精确 GC 与循环终结器

### 2.1 live-OBJ 位图

- 每个函数生成调用帧记录：帧基址、live-OBJ 位图。
- 在 safepoint（函数调用、GC 调用）记录当前存活 OBJ vreg 的位图。
- GC 从活动帧链精确扫描，不再依赖整段栈保守匹配。

### 2.2 根集合

- 参数、局部变量、表达式临时值按位图登记。
- 保留显式根栈作为兜底与合成探针接口。
- 提供 `--gc-conservative` 兼容开关；默认精确扫描。

### 2.3 循环终结器

- 不可达环回收前执行 `__del__`/终结回调，语义对齐 CPython 的可观察时机。
- 终结器异常与重入规则显式定义。
- 合成探针覆盖：单环、双环、带外部引用的环、终结器内重新挂接。

## 3. 质量与性能

- unittest 从 209 提升到 240+；新增 GC/函数对象专项测试。
- 差分语料保持 11/11；生成语料扩到 800+。
- 引入 200 个 CPython 子集程序做输出/退出码差分。
- 性能门槛：list/dict/str 基准不低于 CPython 2x；不达标先修热点。
