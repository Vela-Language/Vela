## 1. 已交付能力

### 1.1 运行期动态函数对象与统一调用约定

- `code` 对象单例缓存：`rt_code_new` 按 `(wrapper_addr, arity)` 缓存不朽 `code` 单例，模块函数值（`m.func`）、`sys.modules[名字].func` 与局部函数名引用共用同一 `code` 对象实例（`is` 与 `==` 成立）。
- 统一 wrapper 与 `rt_code_call_argv`：为每个作为值引用的函数生成 `fn_wrap_<name>(argv: OBJ) -> OBJ`，配合栈上传参支持 0–4+ 任意位置参数与 `int`/`float`/`bool`/`str`/`None`/容器/函数对象任意返回类型。
- `rt_code_call_argv` 严格校验 `code` 类型标签与参数列表长度（arity 不匹配或类型不匹配立即报错退出，退出码 1）。
- 保留静态已知目标的直接调用快路径。

### 1.2 精确 GC（live-OBJ 位图）与循环终结器

- 每个含 `OBJ` 虚拟寄存器与调用点的函数生成 32 字节 GC 帧记录（`prev`、`slots_base`、`live_bitmap`、`obj_count`）并链入 `gc_frame_top`；`TRY_PUSH` / `RAISE` 自动保存与恢复 `gc_frame_top`。
- 在每个 safepoint（`call`、`print`）按活跃区间写入精确 64 位 `live-OBJ` 位图；`rt_gc_collect` 默认沿活动帧链精确扫描根，并通过 `--gc-conservative` 提供保守式栈扫描兼容开关。
- 修复容器子对象传递标记中类型描述符指针比较与 `list`/`tuple`/`set` 元素起始偏移（`+48`），确保无保守栈扫描时仅靠父容器引用的子对象图精确存活。
- 四阶段 PEP 442 循环终结器（`rt_set_finalizer`）：
  1. 根集合（显式根栈、全局槽、活动帧链位图）+ 容器传递标记；
  2. 对不可达对象/环在释放前执行终结器回调（至多执行一次），内置重入保护（终结器内递归 `rt_gc_collect` 安全返回）与异常捕获（记录到 `rt_gc_finalizer_errors` 并继续终结其余不可达对象）；
  3. 若有终结器执行，清空标记并重新扫描根与容器传递子对象，确保终结器内重新挂接（resuscitation 到全局或存活容器）的对象环完整存活；
  4. 清扫仍未标记的不可达对象并清理终结器表项。

### 1.3 质量与性能门槛

- 小对象（`int`/`float`/`bool`/`None`/`str`）48 字节块自由链表池化 + 非参数局部标量寄存器化 + 容器下标覆写/查询临时键即时回收，消除循环内内核堆分配热点。
- `list`、`dict`、`str` 微基准均达到 `≥2.0x CPython`（实测通过 `test_v05.py` 门槛断言，输出逐字节一致）。
- 新增 `tests/cpython_subset.py`（10 类共 200 个 CPython 纯 Python 子集程序），与 CPython 输出及退出码 200/200 一致。
- `tests/corpus_scale.py` 扩展至 800 个生成差分程序，800/800 通过。
