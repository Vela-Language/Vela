# Vela 路线：v1.0 纯 Python 等价，v2.0 复刻 CPython ABI

> 路线 A 定稿（2026-11-21）：**不内嵌 CPython**。
> v1.0 = 完全编译纯 Python（CPython 3.15.2 语义）；v2.0 = 复刻 CPython C ABI，
> 直接加载 cp315 的 `.pyd`（numpy / pygame / Dear PyGui）。

## 0. 范围定义

### v1.0 包含

- 3.15.2 全部语法（含 t-string、PEP 695、match、except*）；
- 纯 Python 语义：对象模型、refcount + 循环 GC、异常、生成器、async、描述符、
  元类、闭包、import（纯 Python 模块）、`eval/exec/compile`；
- 纯 Python 标准库（Vela 实现的子集，见 §3）；
- 原生编译产物，不依赖 `python315.dll`。

### v1.0 不包含

- C 扩展 `.pyd`（numpy、pygame、Dear PyGui、sqlite3 等）；
- CPython C API / ABI、GIL 兼容、`ctypes` 调用任意 DLL；
- C 实现的 stdlib 模块的二进制兼容（`math`、`_json`、`_sre`、`socket`、`datetime` 等）。

### 必须先解决的边界：纯 Python 程序也会 import C 模块

“纯 Python 源码”不等于“无 C 依赖”。典型程序会 `import math`、`json`、`re`、`datetime`。
路线 A 下没有 C ABI，这三条路只能选一条：

| 方案 | 含义 | 代价 |
| --- | --- | --- |
| A1 | v1.0 自带 Vela 版 stdlib 子集（`math` 用运行时内建、`json` 纯 Python、`re`/`datetime` 重写） | 工作量大，但用户可用 |
| A2 | v1.0 只保证语言语义，stdlib 缺失即报错 | 实现快，实际不可用 |
| A3 | 只对少数模块开特例（`math`/`json`），其余留到 v1.x | 折中，推荐 |

**建议 A3**：v1.0 先覆盖 `math`、`json`、`random`、`collections`、`itertools`、
`functools`、`dataclasses`、`typing`、`re`（简化引擎）与 `datetime` 的基本子集；
`socket`、`sqlite3`、`ssl` 等明确留到 v2.0 之后。

## 4. v2.0：复刻 CPython C ABI

> 目标：不内嵌 CPython，提供 `python315.dll` 兼容层，直接加载 cp315 wheel。

### 4.1 任务

- [ ] ABI 基线：从 CPython 3.15 头文件生成结构体偏移断言（C shim + `static_assert`）
- [ ] `PyObject`/`PyVarObject`/`PyTypeObject` 完整布局
- [ ] refcount、GIL、`PyThreadState`、`PyInterpreterState`
- [ ] 异常 API、`PyArg_ParseTuple`/`Py_BuildValue`、vectorcall
- [ ] 类型系统：`PyType_Ready`、heap type、PEP 489、buffer protocol
- [ ] C API 导出表：按 3.15 符号清单逐项实现
- [ ] `python315.dll` 兼容构建（或替代 DLL + 导入重定向）
- [ ] ABI 测试：自建 C 扩展逐项验证；CPython `_testcapi` 子集
- [ ] 生态验证：numpy → pygame → Dear PyGui
- **Gate**：三个库的基础用例通过；numpy wheel 可加载并完成数组运算。

### 4.2 现实判断

- 这不是“补一层函数表”，而是重写 CPython 的对象模型、refcount、GIL、异常与类型系统；
- 工作量与 v1.0 **同量级或更高**，且失败模式是进程崩溃，不是报错；
- Dear PyGui 是 C++（ImGui），还需处理 C++ ABI 与回调；
- pygame 是 LGPL，动态链接与再分发需要合规审查；
- v2.0 需要独立的 ABI 计划与持续集成（用 C 编译器构建测试扩展）。

## 6. 主要风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| refcount 可观察语义 | 测试集大量失败 | v0.3 就按 refcount 设计，不做纯 tracing GC |
| 纯 Python 程序的 stdlib 依赖 | 实际不可用 | A3 清单优先，缺失模块明确报错 |
| `re`/`datetime` 重写 | 工期膨胀 | 先做常用子集，逐版扩展 |
| v2.0 ABI 崩溃 | 生态不可用 | 单独计划、逐符号测试、先做 `_testcapi` |
| 线程/GIL | 并发行为不一致 | v0.6 引入 GIL，明确单线程/多线程边界 |
| 性能 vs 动态语义 | 变慢 | 守卫 + 内联缓存 + 分层编译 |

## 7. 工作方式

1. 每阶段先写验收测试（CPython 子集 + 差分语料），再实现；
2. 每完成一项勾选，跑 unittest + 差分；
3. 每阶段发 `v0.x.0` 稳定版与 `v0.x.y-dev.N`；
4. 不达标只回退该阶段，不跳版本；
5. v1.0 前不做 C ABI 相关代码，避免两条战线同时开工。
