# Vela 路线图

> 对标版本：Vela v0.1.0 · 目标平台：Windows x86-64

## 0. 目标与非目标

**目标**：让模型写出的 Python 代码在不改源码的前提下获得原生的数值/调用性能，
并逐步扩展到对象、异常、模块与生态互通。

**非目标**：跨平台（Linux/macOS 不碰）、多后端（不使用 LLVM）、
编译器自举（用 Python 写编译器是可接受的工程选择）。

## 1. v0.1 — 可编译子集的端到端闭环（已完成）

- 自有 x86-64 编码器 + PE32+ 直出，零外部工具链；
- 单态类型推断、CFG IR、线性扫描分配；
- int64 / f64 / bool / str / None，函数、递归、循环、短路布尔；
- 运行时：打印、Python 语义整除取模、溢出/除零诊断；
- `vela build/run/check/bench`，超纲文件回退 CPython；
- 44 个 unittest + 11 个差分语料 + 10 张对比图（9–53x CPython）。

## 2. v0.2 — 对象模型与异常

> 目标：能编译"普通业务脚本"，不再只是数值内核。

- 堆分配器（bump + 空闲链表）与 GC（从引用计数起步，后续可换分代）；
- `list` / `dict` / `str` 的索引、切片、拼接、成员测试；
- 字符串格式化、f-string 子集；
- 异常：`try/except/finally/raise`，SEH 或自带 unwind 表；
- 闭包、嵌套函数、模块级全局变量；
- 参数传递扩展到任意个数（栈传参）、关键字参数；
- 内建库：`math`、`sys`、`time` 的最小可用子集。

验收：能编译并正确运行 500 行以内的典型脚本；对象密集基准 ≥ 2x CPython。

## 3. v0.3 — 动态层与 CPython 互通

> 目标：对"模型写的真实 Python"做到高覆盖率，而不是只覆盖类型完美的子集。

- 带标签的值表示（tagged pointer / NaN-boxing）与去优化（deopt）；
- 类型反馈：热点函数记录参数类型，生成带守卫的专用版本；
- 内联缓存：属性访问、方法调用、全局查找；
- 通过 `python3xx.dll` 嵌入 CPython 作为**兼容运行时**：
  未编译的模块（numpy/torch 等）直接调用 CPython API；
- `import` 语义：native 模块优先，缺失时落到 CPython；
- 调试信息（行号表）与崩溃栈回溯。

验收：`vela run` 对绝大多数纯 Python 包无需回退；回退仍保留。

## 4. v0.4 — 优化中端

> 目标：代码质量接近 rustc -O 的可比区间，并用同一基准实测。

- SSA 形式与基于 SSA 的优化：GVN、常量传播、DCE、LICM；
- 内联（代价模型）、尾调用、去虚拟化；
- 逃逸分析 + 栈上分配；
- 大整数：int64 溢出走堆上 bigint（Python 语义完整化）；
- 除法强度削减（不变除数）、循环展开、指令调度；
- 寄存器分配升级：区间分裂、move 合并、图着色对照实验。

验收：`fib`、`primes`、数值循环与 `rustc -O` 同机对比，差距 ≤ 1.5x；
对象密集场景 ≥ 5x CPython。

## 5. v1.0 — 完整 Python 子集 + 生态

- 覆盖 CPython 语言参考的绝大部分语法（含生成器、async、模式匹配）；
- 完整异常语义、描述符协议、元类的最小支持；
- 包管理：`vela build` 生成单文件 exe 或带依赖目录的发布包；
- 性能剖析器、`--emit-asm`、源码级单步调试；
- 文档、教程、与 IDE 的 LSP 集成（可选）。

## 6. 关键工程决策与风险

| 决策 | 理由 | 风险 |
| --- | --- | --- |
| 复用 CPython parser | 语法兼容性零成本 | 语法版本绑定宿主解释器 |
| 不用 LLVM | 完全控制后端，编译极快，Windows 专项优化自由 | 必须自建优化管线，追赶 rustc 成本高 |
| 先静态子集、后动态层 | 先拿到可验证的性能与正确性 | 动态层（v0.3）是最大工程量 |
| 只做 Windows x64 | 调用约定/PE/异常模型可以硬编码 | 生态与用户面窄 |
| Python 写编译器 | 开发效率、模型友好 | 编译速度受解释器启动限制（单文件仍 <2 ms） |

### 关于"比 Rust 更好"

这是一个**可检验的工程目标**，不是口号。当前 v0.1 只证明了"比 CPython 快 9–53x"。
要宣称超过 rustc，至少需要：

1. 同一台机器、同一算法、防优化（black_box）的对照基准；
2. 覆盖调用密集、分支密集、内存密集三类负载；
3. 公开测量脚本与原始数据。

在此之前，文档与对外表述不使用"超过 Rust"的说法，只陈述实测结果。
