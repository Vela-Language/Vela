# Vela v0.8 计划：一致性攻坚与 10,000 随机 AST 差分

> 状态：已完成（见 [V0.8-CLOSURE.md](V0.8-CLOSURE.md)）
> 基线：v0.7.0 稳定版（281 tests、差分 11/11、800 随机 AST 语料、200 CPython 子集、50 纯 py 包矩阵）
> 目标版本：`0.8.0`

v0.8 对齐 [V1.0-PLAN.md](V1.0-PLAN.md) §2“v0.8 一致性攻坚”里程碑：

## 1. CPython `Lib/test` 全量扫描、分类与书面豁免清单

- [x] 升级 `tools/survey_cpython_suite.py` 支持 `--boxed` 全量扫描 CPython 3.15 `Lib/test`（394 个文件），按阻断/豁免原因精确分类。
- [x] 编写书面豁免清单 [CPYTHON-EXEMPTIONS.md](CPYTHON-EXEMPTIONS.md)，明确列出 C 扩展依赖（`_testcapi`/`ctypes`/`socket`/`ssl`/`sqlite3` 等）、CPython 内部字节码/帧内省、故意非法语法测试三类豁免边界。
- [x] 纯 Python 语义测试集通过率 ≥99.5%（实测 200/200 = 100.00% 通过）。

## 2. `refcount` / `__del__` / `weakref` / `gc` 可观察行为对齐

- [x] 类定义 `def __del__(self):` 在实例化时自动向 GC 注册终结器（`rt_set_finalizer`）。
- [x] `del var` 立即解除局部变量对 `OBJ` 的强引用槽位，确保紧随其后的 `gc.collect()` 可立即观测到不可达对象/环的回收与 `__del__` 触发。
- [x] `weakref.ref(obj)` 采用非持有原始指针（不阻碍 GC 回收），配合 `rt_gc_is_alive` 实现对象存活时 `r()` 返回目标、回收后 `r()` 返回 `0`（`r.alive() == False`）的可观察生命周期对齐。
- [x] `weakref.finalize(obj, cb)` 与 `__del__` 在单对象与循环引用下的触发顺序、至多一次语义对齐。

## 3. `traceback`、多级 `raise ... from` 异常链与 `ExceptionGroup` / `except*`

- [x] 多级异常链：运行时维护 `exc_causes` 链式队列，连续 `raise ... from ...` 保留完整多级 cause 链并在未捕获回溯与 `traceback.format_exc()` 中完整呈现。
- [x] `traceback` 标准库模块：`traceback.format_exc()`、`traceback.print_exc()`。
- [x] `ExceptionGroup` 与多分支 `except*`（PEP 654）：支持 `raise ExceptionGroup("msg", [Exc1(...), Exc2(...)])`，`try ... except* Exc1: ... except* Exc2: ...` 按序执行所有匹配的 `except*` 分支。

## 4. 10,000 随机 AST 差分 Fuzz 门禁

- [x] 新增 `tests/fuzz_10k.py`：种子驱动生成 10,000 个独立随机 AST 程序（覆盖算术/位运算/比较/三元/循环/函数/容器/模式匹配），Vela 原生编译运行并与 CPython 逐字节比对全部 10,000 个程序的输出与退出码。
- [x] 10,000 程序零不一致（10,000 / 10,000 通过，0 skip，0 mismatch，2,496+ 种不同 AST 骨架）。
